# PIHC3 r3 — state localization fix

Release: `unified-20260906-r3`. This is the r2 game content with corrected publication paths for the state-name and victory-point localization tables. All 35,559 game-file contents remain byte-identical to r2; six files move to the vanilla-relative paths under `localisation/<language>/`.

## Problem and correction

State 4 displayed vanilla **下奥地利** instead of authored **驼丁汉 / Trottingham**. The source translation was present and correctly encoded. The project-wide localization postprocessor relocated the state family's aggregate tables to `localisation/replace/<language>/`, leaving vanilla's original state table present at its normal path.

The state family now keeps its aggregate tables at the exact paths used by vanilla, including `localisation/simp_chinese/state_names_l_simp_chinese.yml` and its English/Russian counterparts. Victory-point tables follow the same rule. Publication metadata retires both previous nested and flat replacement paths. Other families retain their existing localization routing.

Chinese, English, and Russian remain separate files with separate language headers. No state IDs, state histories, authored translations, gameplay scripts, or M6/Rock Farm content are changed. This is a source-level compiler-extension correction, not a manual deployment overlay.

## Verification

The wrong state label was reproduced in the running Chinese HoI4 1.19.2 campaign. After publishing the state table at vanilla's exact relative path and restarting, an in-game state-scope query for state 4 resolved to **驼丁汉**. The current campaign was preserved in a separate local save before restarting; no existing save was overwritten.

Ten targeted localization-postprocessor tests pass, including a new regression that builds native state-family tables against conflicting vanilla English and Chinese entries, verifies the direct output paths and language-specific values, and checks obsolete-path cleanup metadata. Existing language-separation, deduplication, and targeted-publication tests continue to pass.

The earlier replacement-folder layout experiments did not resolve the observed label and are excluded from this release. English output is checked structurally and against the authored Trottingham value; this fix's direct runtime verification was in Chinese. The broader r2 smoke-test scope and inherited runtime limitations remain documented in the [r2 report](unified-20260905-r2.md).

## Build and use

Build with the pinned compiler in `requirements-build.txt`, then run `python3 scripts/verify_release.py <compiled-PIHC3-directory>`. The default verifier now uses `unified-20260906-r3-files.json`.

Restart HoI4 after installing this fix so it rescans the localization files. When updating an r2 installation, remove the old state-name and victory-point YML files from `localisation/replace/<language>/`; the full compiled r3 repository/package already has the correct layout. Source builds with publication tracking retire these old paths automatically.
